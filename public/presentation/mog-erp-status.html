Why this system exists

لماذا نبني هذا النظام

The problem
Kitchen equipment projects span sales, technical office, production, warehouse, purchasing, logistics, and installation. Paper and spreadsheets fragment the truth.
The goal
One shared record per project: same customers, products, materials, approvals, and stock movements for every team.
How we build
Full lifecycle designed in the data model first. Workflows ship vertically when they are operationally ready, with legacy bridges so the company can start using the system now.

Go-live strategy

Legacy bridges (intentional)

الجسور المرحلية

  • Legacy contract reviews — enter paper CR / WO numbers, units, and serials without waiting for the full sales CRM.
  • Legacy issue permits — warehouse can record issues while native inventory issue posting is finished.
  • Data seeding — historical materials, products, BOMs, customers, and receipts imported so the system starts with real company data.

These are coexistence tools, not permanent shortcuts. Each bridge retires when the native workflow ships.

MOG ERPStatus review

Phase A detail

Why stock truth comes first

لماذا نبدأ بحقيقة المخزون

Without it

  • Receipt documents exist, but material on-hand can stay out of sync
  • Production and maintenance consumption is hard to trust
  • Reports and buying decisions rest on incomplete stock

With it

  • Requisition demand reflects real shortages
  • BOM issues link to real jobs
  • Legacy issue permits can wind down
  • Procurement vertical becomes a closed loop

Phases B and C then attach the customer project path and field work onto a stock foundation that is already trustworthy.
